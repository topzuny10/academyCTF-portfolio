## 실행 흐름 제어
	run(r) <프로그램 인자>: GDB에서 프로그램을 실행하는 명령어(인자가 없으면 run만)
	
	break(b): 특정 주소에 중단점(BreakPoint)을 설정, 단 0x401156(예시) 주소에 직접 중단점을 설정하려면 *붙이기
	
	continue(c): 중단된 프로그램을 계속 실행, 중단점이 여러개일 경우 continue(c) <숫자>도 가능
	
	context(ctx): 프로그램이 중단점에 도달했을 때 자동으로 실행되는 명령어로 프로그램에 대한 상세한 정보들을 출력함
	REGISTERS: 레지스터의 상태를 보여줌
	DISASM: rip부터 여러 줄에 걸쳐 디스어셈블된 결과 출력
	STACK: rsp부터 여러 줄에 걸쳐 스택의 값들 출력
	BACKTRACE: 현재 rip에 도달할 때까지 어떤 함수들이 중첩되어 호출됬는지 확인
	
	entry: 진입점으로부터 프로그램을 분석할 수 있게 해줌
	start: gdb에서 프로그램을 실행하고 main()의 위치를 찾아 멈춤
	readelf:ELF(리눅스 실행파일 형식) 파일을 분석하기 위한 도구, 진입점 정보와 ELF파일의 다양한 정보를 분석하여 제공함

## 실행 흐름 추적하기
	ni(Next Intruction): 함수 내부로 들어가지 않음
	si(Step Into): 함수 내부로 들어감
	finish: 함수를 끝까지 한 번에 실행함

## 디버깅을 위해 자주 사용되는 명령어
	info(i): 정보를 보여줌
	info registers(i r): 레지스터의 값을 확인하고 싶을 때 사용된다
	info breakpoints(i b): break 명령어로 설정한 중단점들을 확인할 때 사용되며 비활성하거나 활성할 수 있다. 비활성: disable <숫자> / 활성: enable <숫자> / 삭제: delete <숫자>
	
	disassemble(disass): 기계어를 디스어셈블로 출력
	u, nearpc, pdisass: 디스어셈블 명령어로 디스어셈블된 코드를 기독성 좋게 출력해준다
	
	x(examine): 특정 주소에서 원하는 길이만큼의 데이터를 원하는 형식으로 인코딩하여 볼 수 있다. x/<포멧 및 크기>형태로 사용된다. 여러 값을 볼 때는 x/<개수><포멧 및 크기>를 쓴다
	포멧: x(16진수) o(8진수) d(10진수) u(부호 없는 10진수) t(2진수) f(float) a(주소) i(명령어) c(문자) s(문자열)
	크기: b(1 byte) h(2 byte) w(4 byte) g(8 byte)
	
	telescope(tele): 메모리 덤프 기능으로 특정 주소의 메모리 값들을 보여주며 메모리가 참조하는 주소를 재귀적으로 탐색해 값을 보여준다
	
	vmmap: 가상의 메모리 레이아웃을 보여줌. 어떤 파일이 매핑 된 영역일 경우, 해당 파일의 경로까지 보여준다
	
	backtrace(bt): 콜 스택(Call Stack)으로 어떤 프로그램이 실행되는 동안 호출되는 순서를 확인할 수 있다
	
	dump memory:프로세스의 메모리 상태를 파일로 저장할 때 사용되며 dump memory <파일명> <시작주소> <끝주소>로 사용된다
	
	set: 프로세스의 메모리 상태를 변경할 수 있는 명령어, set <주소/레지스터> = <변경할 값>으로 사용된다
